# Transpono

This Flutter app has six native visual panels and is connected to the
`player_core` package. The functional local-media player exposes file
selection, Play/Pause, Seek, fullscreen video, and experimental Android-only
pitch/speed controls for local audio plus an initial A/B loop. Its colors and
hierarchy follow the supplied panel references.
The sample does not loop: natural completion shows `Faixa terminada`, and
`Recomeçar` is an explicit user action.

## Main player and chord sheet

The main video scrolls with the page by default. Its pin button fixes it while
the controls below scroll; tapping again releases it. The same browser/video
session remains mounted. Tap the video to reveal Play/Pause, ten-second jumps,
seek and fullscreen for two seconds. The title, browser label and seek row are
not repeated beneath the video. A pending YouTube recovery shows only the
**Restaurar vídeo** action.
Cifra starts OFF, with the original pitch, speed and A/B cards below the video.

**Cifra**, beside **Abrir ficheiro**, opens an in-app browser with Cifra Club and
Cifras.com.br, site-filtered web search and direct links. A user-selected public
chord page can be previewed and confirmed for import. No hidden APIs, batch
scraping, login/paywall/challenge bypass, or automatic song recognition is used.
Website changes/access restrictions may prevent import; compatibility is not a
provider partnership or permission to redistribute. Provider terms/licensing
remain a publishing gate. Sources with free browsing are preferred.

With Cifra ON, the sheet replaces those cards and the gear INSIDE the video opens
compact pitch/speed/A-B/seek controls within that same box. Toggle Cifra OFF to
restore cards without deleting saved text. Search on the sheet chooses another
version.
The **Acompanhar áudio** switch (labelled **Tom ligado ao áudio** / **Tom só da cifra**)
couples chord transposition to confirmed audio pitch; turn
it off for independent +/- semitones. Repor cifra resets only the chord display.
Original text and source attribution persist by track, preserving timed cues.
The reader retains chord start columns and handles slash chords/ChordPro tags.
Without a selected source, imported text is retained only during the app session.
Text is limited to 10,000 characters / 500 lines; PDF/image recognition is absent.

Sequential contract and verification: `../../docs/PLAYER_CIFRA_SEQUENTIAL_PLAN.md`.

## Run

On Windows, from `apps/mobile`, build and open the isolated development app:

```powershell
.\tool\run_dev.ps1 -DeviceId <device-id>
```

### Development on this Windows PC

Use the isolated **Transpono Dev** app while retaining the existing Transpono
installation and its data. From `apps/mobile`:

```powershell
.\tool\run_dev.ps1 -DeviceId R58YA16NDVM
# Compile without installing:
.\tool\run_dev.ps1 -BuildOnly
```

This checkout was created with Flutter **3.47.5** (Dart **3.13.4**).
Android builds are limited to two Gradle workers, a 2 GB Gradle heap and a
512 MB Kotlin heap to fit the development PC's approximately 6 GB of RAM.
The runner uses Flutter at `%LOCALAPPDATA%\Codex\Toolchains\flutter`, builds
`lib/main.dart`, checks APK metadata for `com.example.transpose_mobile.dev`,
then installs with `adb install -r`. It never automatically uninstalls an app.
Use `-FlutterPath` and `-AndroidSdk` to override the tool locations.
The Dev app has its own empty storage; existing sessions are not copied.

The first run generates a dedicated development key at
`%USERPROFILE%\.android\transpono-dev.keystore`. Keep a private backup outside
Git and copy it to future development PCs to preserve Dev app updates.
This is a development-only key (alias `transponodev`, conventional password
`android`), not a publishing key. `TRANSPONO_DEV_KEYSTORE` can override its path.

For hot reload, after the first successful setup, in PowerShell:

```powershell
flutter run -d R58YA16NDVM --target=lib/main.dart --android-project-arg=transponoDev=true
```

The Gradle property applies only to normal targets. Integration-test targets
always keep the isolated `.qa` package and do not use the Dev signing key.
Without the property, the original package and signing configuration remain.

## Android integration-test safety

Targets under `integration_test/` now compile as the separate
`com.example.transpose_mobile.qa` app. Normal `lib/main.dart` builds retain the
production ID. **Always use `--keep-app-running` with `flutter drive`: its default
cleanup uninstalls the target.** Prebuild and verify the QA APK before passing
`--use-application-binary`; a driver initialized from an older APK can otherwise
retain that older package identity. Never use `pm clear` or uninstall production
to test process death. The safe recovery runner is `tool/run_recovery_probe.ps1`;
see `../../docs/RECOVERY_RESEARCH_AND_QA.md` for the incident and instructions.

The sample is `assets/qa_tone.wav`, generated by
`dart run tool/generate_qa_tone.dart`. It is a quiet 440 Hz tone, not a musical
recording. Imported files are selected with the OS picker and stay local.

The Android debug build also compiles a C++ FFI/Oboe tone-output library for
the audio-engine spike. It is not connected to the app's media playback. The on-device test is
`flutter test integration_test/audio_core_ffi_test.dart -d <android-device>`;
see `docs/AUDIO_SPIKE_PROGRESS.md` for its limited result.

For the license-free pitch/speed direction in ADR-014, an Android-only,
isolated Media3 probe is tested with `flutter drive --profile --keep-app-running
-d <device-id> --driver=test_driver/android_native_processing_probe_test.dart
--target=integration_test/android_native_processing_probe_test.dart`. It is
not exposed in the app UI and must not be run alongside the product player on
the same resource. The normal build excludes Rubber Band.

## Important limits

- The app opens a Transpono shell recreated from the six
  supplied references with resolution-independent Flutter text, cards and
  icons. Main/fullscreen controls share a single player; Practice, Stage and
  manual Chords use its acknowledged state. Presets and the setlist support
  local CRUD. Reference HTML/images remain separate from the functional UI.
  Production startup now enables SQLite session recovery, paused local restore
  and an explicit YouTube restore action. New local imports use app-support
  storage, not just picker cache. See `../../docs/CURRENT_ARCHITECTURE.md`.

- The Player search button opens YouTube inside Transpono. Search results,
  titles, thumbnails and selection stay in the embedded browser. The selected
  video's browser panel has playback, speed, experimental pitch and A/B controls.
  Pitch uses bundled MIT-licensed Signalsmith Stretch Web only when
  the existing video exposes a compatible same-origin Blob source. Failures
  leave pitch unapplied and report a message. No stream URLs are extracted and
  no media is downloaded into the local-file player. This browser path is
  separate from Media3; iOS compatibility is not established. See
  `docs/YOUTUBE_INTEGRATION_DECISION.md` for evidence and remaining limits.
  AudioWorklet is preferred; pages that reject its Blob module use the same
  WASM DSP through a 2048-frame ScriptProcessor compatibility adapter. That
  adapter adds latency and depends on the page's UI-thread load.

- Android local audio now uses one Media3 output for Play/Pause/Seek and
  pitch/speed together; video still uses the `video_player` pilot. iPhone and
  video do not yet expose pitch/speed controls. Media3 parameter ACK is not
  proof of acoustic quality, latency or glitch-free switching.
- The Android A/B controls clip and repeat on that same Media3 player. Seeking
  outside disables repeat but retains markers. A/B can be edited while repeat
  is active; invalid boundaries are rejected before changing the player.
  Accuracy, clicks, edit latency and long-run drift are unverified; saved loops
  are not implemented.
- Its Play/Pause futures acknowledge platform commands; they do **not** prove
  first audible output or acoustic silence. AUD-001/002 latency acceptance
  needs external instrumentation on devices.
- Fullscreen reuses the existing session and media controller. Video fills the
  display (cropping to fit); controls appear on tap and hide after 2.5 seconds.
- Background playback is not supported yet: the app pauses on lifecycle exit
  and does not auto-resume. Interruptions/audio focus and the remaining route
  flows are later backlog tasks. Do not treat this build as release-ready.
- The generated package identifier `com.example.transpose_mobile` and debug
  signing are placeholders. A production Android release and iOS signing will
  need the user's identifiers and signing credentials.
